# What works

This is the long version of the README's summary: every surface in the window and the CLI, its
state, and the reason to believe it. Anything deliberately unfinished is listed as such.

| Surface | State |
|---|---|
| Shelf: search, rows, detail, evidence table, variants | **real**: SQLite FTS5 over `index.db`, offline, `skills.search`/`skills.load` over IPC |
| Shelf: static review | **real**: six capability rules with `file:line` evidence, grade from the same scan the prototype used |
| Shelf: source health | **real**: `ok` / `stale` (with last-sync date) / `broken`, plus the last attempt and failure count, read without a network call |
| Shelf: auto-refresh | **real**: at launch and every five minutes while the window stays open, the index refreshes whatever is due, off the UI thread, unless the switch is off. Fresh sources cost no request; a stale source is re-synced; a broken one retries on a bounded backoff from five minutes to six hours. The shelf status line and Settings re-read the result, and a successful pass pushes `rigel://skills` so the list reloads without reopening. Settings → Skill shelf shows each source, refreshes on demand and indexes a repository. `rigel skills refresh` is one pass, and `rigel skills watch` runs the same loop headless; all faces share one implementation |
| Shelf: empty state | offers "Index repository" when no source has ever synced |
| Cloud | **real, opt-in**: a Firebase project the user owns — Identity Toolkit email/password sign-in, account creation, password reset and email verification with a send/resend control on the account page (`rigel cloud verify`, `--check`; the refresh token and the verification answer live in the OS keychain, never the renderer, and a reset answer does not reveal whether the account exists), Firestore REST under per-user rules, Push/Pull mirroring shelf metadata while bodies stay local, **deletion tombstones** from a per-account manifest (`cloud-state.json`) with a visible last-push/last-pull clock in Settings → Cloud and `rigel cloud status`, and **Publish to phone** writing one session's prompts and assistant text to `users/{uid}/sessions/{id}/turns` (tool calls, command output and the project path excluded), and optional **Firebase App Check** through a custom provider shipped in `functions/`: it verifies a per-install client token in constant time, rate-limits each installation and address with Firestore token buckets, and mints tokens with the Admin SDK; `rigel cloud app-check --url`/`--client-token` or Settings → Cloud → App Check stores the endpoint and keeps the client token in the OS keychain, tokens are cached in memory and attached as `X-Firebase-AppCheck` to every Firebase request, and the endpoint, the client credential and the token provider's contract (token, Unix-second expiry, fail-closed errors) are covered by unit and fake-server tests (`ios/RigelPhone/Tests/RigelRoomKitTests/CloudKitTests.swift` covers the phone's). The iPhone client signs in to the same project and lists/reads those documents, with its decoder covered by `ios/RigelPhone/Tests/RigelRoomKitTests/CloudKitTests.swift`. Exercised end to end against a local stand-in for all three Firebase hosts (`crates/rigel-core/tests/cloud.rs`); **not** exercised against a live Firebase project on this machine, because the repository does not own one |
| Plugins | **real**: a `plugin.json` manifest (schema 1, unknown fields refused), a short-lived child per tool call with a scrubbed environment, and a capability broker that canonicalises every `fs.read`/`fs.write` against the declared roots and denies anything else with an error object that carries no bytes; `env.get` is allowlisted name by name. Installs live in `<index>/plugins/<name>`, carry a tree SHA-256 and the reviewed manifest's hash (a rewritten manifest is refused rather than widening its grant), and can be enabled, disabled or removed without touching the tree on disable; a broken tree is listed with its parse error and can still be removed. Pinned catalogue installs require a full 40-character commit and verify `rev-parse HEAD`. `plugin_call` is one registry tool, so the permission matrix, role narrowing, overrides and read-only child rules apply. Tests: 13 unit tests in `plugin` (including a real Python child refused `../secret.txt`) and 11 in `tests/plugins.rs`, including a disabled plugin leaving the next turn's `Tools::specs`. **Known limits:** subprocess plugins only, no hooks, and the broker does not intercept a plugin's own syscalls — `network`/`process` are declarations, so review the tree and use an OS sandbox where available |
| Plugin marketplace | **real**: `crates/rigel-core/src/plugin/catalog.json` is compiled in and searchable offline; entries carry `official`/`verified`/`community` tiers, shelves, author, version, source, licence, capabilities, an honest note and an exact install command. `rigel plugins browse\|search\|info\|install` and the Shelf's Plugins tab install a skill entry into the index and both harness stores, or a bundled/pinned plugin into the store; enable/disable/remove, receipt source and broken installs are shown. The catalogue has 2,533 entries: nine bundled skills, the first-party `rigel-hello` plugin, and 2,523 external marketplace listings from Anthropic's official and community Claude directories and `wshobson/agents`. External entries are discovery-only and name their upstream plugin-manager command. `e2e/specs/plugins.spec.ts` drives the real window through install, receipt, toggle, tampered-manifest error, broken removal and clean removal. No hosted registry and no automatic refresh |
| Native skills | **real**: nine reviewed `SKILL.md` bodies are compiled in (`skillevaluator`, `headroom`, `ag-ui`, `mcptoon`, `llmfit`, `semble`, `cognee-evaluate`, `blender-mcp`, `superpowers`), indexed as `builtin:<slug>` at window launch and by `rigel skills builtin`, so shelf search, the palette, `skills_search`, `skill_load` and session pins all work offline. `--install` copies the same bytes into `~/.agents/skills` and `~/.claude/skills` and is never run on launch. NVIDIA SkillEvaluator (Apache-2.0) was installed and run on `skills/builtin/*`: the eight original skills pass the required check with grade A (90.0–96.2/100); `superpowers` was added after that sweep and follows the same frontmatter and body rules. Licences were verified for the eight; Cognee is evaluate-only, not a migration. `superpowers` is a Rigel-native adaptation of the MIT-licensed obra/superpowers workflow |
| GitHub source | **real**: parse `owner/repo` or any GitHub URL, one tree call, raw bodies, ETag cache |
| SkillsMP / SkillHub | **real** via `rigel skills sync`; metadata only, no bodies (they have none to give) |
| Duplicates | **real**: SimHash ≤ 3 bits, clusters computed after every ingest, variants listed under the row |
| Evidence | **real**: advertised percentages from the description, `unmeasured` until a measurement exists, and `audited` for a dated third-party verdict |
| skills.sh import | **real**: `rigel skills import --skills-sh <page>` indexes just that skill's body and stores the page's Gen/Socket/Snyk verdicts as dated evidence rows (`audit:socket=pass`). A verdict never changes Rigel's own grade; a page without an audit section is refused rather than read as a pass |
| CLI | `rigel skills search|get|remove|index|status|sync|sweep|stats|import|gc|refresh|watch`, all with `--json`, §7.2 exit codes; `import --from <file>` for the prototype export, `import --skills-sh <url>` for one skills.sh page. `rigel models [--provider …] [--all]` prints the picker's merged roster (`--all` includes image, video, audio and retrieval rows) |
| Handoff prompt | **real**: `rigel handoff` selects the newest unfinished session (or `--session`), carries the project rule set (`AGENTS.md` winning over `CLAUDE.md`, plus `.cursor/rules`) verbatim with repeatable `--constraint`s, lists the session's `file_change` paths and the current `git status`, and prints a bounded `git diff --stat`. Open questions come from `--open-question` and the latest turn's error rows; the proposed plan is labelled unverified. `--json` exposes the components and the prompt; `--out` writes it. The prompt marks nothing done and labels the last model output unverified. `cargo test -p rigel-cli --test handoff` round-trips the output into a new session with the rules intact and no checked boxes |
| Cloud CLI | **real**: `rigel cloud status\|configure\|login\|sign-up\|reset\|logout\|push\|pull\|sync\|publish\|app-check`, each with `--json`; the password and the web API key are read from stdin, the refresh token never leaves the keychain, and the exit codes follow §7.2 |
| Native agent | **real**: OmniRoute (local router, autostarted; default `gpt-5.6-sol-medium`), OpenRouter and Gemini (`gemini-4-argon` by default) streaming with retries, a deterministic scripted model, a path-checked native tool set including Roblox Studio and sound generation, skills pinned per session |
| Provider adapters | **real**: one table (`crates/rigel-core/src/agent/providers.rs`) behind the chat layer — OmniRoute, OpenRouter, Gemini on AI Studio, **Gemini on Vertex AI** (project and location in the URL, an OAuth access token, `google/gemini-…` ids), **Anthropic** (`claude-…` ids, default `claude-opus-5-5`), and the OpenAI-compatible vendor endpoints (OpenAI, xAI, Groq, DeepSeek, Mistral, Together, Fireworks, and Meta Model API for Muse Spark and Muse Wonder). The app and the CLI build every turn from the same row, Settings renders that table through `providers_list`, the picker reads each vendor's own `/models` where one is published, and a model id that names a batch endpoint — or another door's namespace — never reaches the wire. Anthropic is the one row whose contract is not `/chat/completions`: `crates/rigel-core/src/agent/anthropic.rs` speaks the Messages API — `Authorization: Bearer`, the system prompt hoisted to a top-level field, a required `max_tokens`, tool results as `tool_result` blocks on a `user` turn, named stream events, and a dated `anthropic-version` on every request including the roster. `temperature` is sent to no other door and is **not** sent here either: API version `2026-10-21` removed the sampling parameters and answers a request carrying one with a 400; effort goes as `output_config.effort` instead of a `thinking` budget, which current models reject. Anthropic is also the only door sent explicit prompt-cache breakpoints — the last tool, the system block and the last message block, three of the API's four — while the automatically caching doors are left untouched; the usage row shows the provider-reported cache reads and writes, and a saving only when a reported read can be priced from a published row. Verified against the platform docs and the vendor endpoints' documented bases; on this machine OmniRoute, OpenRouter, Gemini, OpenAI and Anthropic hold credentials, and the Anthropic one is refused by the provider (`401 invalid x-api-key`), so the adapters are exercised by the unit tests' scripted servers rather than a live turn |
| Provider routing | **real**: the renderer sends the provider **with** the model on every turn and quote, and one core resolver (`agent::routing`) decides the pair from the saved settings, the renderer's pick, a role preset, an agent row or Free mode. A model the named door cannot send is an error, never a quiet default; a model id can never select Vertex (its `google/gemini…` namespace is also OpenRouter's spelling), so a Vertex request happens only when Vertex is selected. A picker pair beats a save that has not landed yet. Tests: `agent::routing`, including a credentialed-but-broken Vertex row that every other pick routes around |
| Provider-key validation | **real**: saving a chat provider key checks the candidate before writing it to the keychain. The default proof is the provider's `/models` with that candidate; OpenRouter uses `/api/v1/key` because its roster is public, and Gemini AI Studio and Vertex are reported as unchecked because they publish no roster. A rejection names the provider and leaves the previous key in place. The core path is shared by Settings and `rigel keys set`; scripted 200/401 tests live in `agent::catalog` |
| Model roster | **real**: a stored key is the permission to use a door, so the picker **merges every credentialed provider's roster** (capped at six, current provider first, OpenRouter offered with no key because its list is public) and tags each row with its door; a provider that publishes no roster contributes its own default, labelled as such, and one dead roster is reported rather than emptying the list. `crates/rigel-core/src/agent/catalog.rs` holds it so the window and `rigel models` cannot disagree. Live on this machine: **1 222 rows** — 629 router, 464 OpenRouter, 128 OpenAI, 1 Gemini default — with provider chips, search and a **chat-only filter** in the picker — on by default and saved as `chat_models_only`, so the toggle survives a restart: a row is hidden only when the vendor declares every output non-chat or its id names a non-chat family (phrase-matched, so `dva/inkling-*` survives `kling`), which held back **212 of 1 222** when measured (185 router, 25 OpenAI, 2 OpenRouter); the toggle shows the rest, and `rigel models --all` prints them with a `non-chat` tag. The counts track the vendors' live rosters, so they drift between readings |
| Roblox Studio | **real**: `roblox_studio` drives Studio's official MCP server — script read/search/grep and multi-edit, Luau execution, textured mesh, material and procedural-model generation, asset search/insertion, playtesting, and viewport capture — with a live `tools/list` and `studio_id` discovery. Read-only tools run directly; place-changing calls use the same approval card and scopes as commands. `roblox_sound` synthesizes deterministic PCM WAV sound effects locally (`ambient`, `click`, `explosion`, `footstep`, `jump`, `laser`, `pickup`, `whoosh`) for Studio Asset Manager import, because Studio MCP has no audio generator. When Studio is installed, the same stdio server is added to `.mcp.json` for Chat-room harnesses. Tests: `agent::roblox` (bounded initialize → tools/call handshake, unknown tools classified as writes, WAV header/duration/determinism, path-safe names); the [EL4CTEO/roblox-skills](https://github.com/EL4CTEO/roblox-skills) pack (23 MIT skills) is a normal GitHub source — press **Index Roblox skills** in Settings → Skill shelf or run `rigel skills index EL4CTEO/roblox-skills`, and the Roblox tool points the agent at the matching `roblox-*` skill; the setup and animation recipes are in [roblox.md](roblox.md) |
| Commands | **real**: `run_command` shows the exact text, cwd and timeout before anything runs; cwd is jailed to the project, output is capped at 64 KB per stream, the process is killed at its timeout, and the exit code is recorded as a `command` item. `--approval ask\|allow\|deny`; `--json` defaults to deny. **Q243:** a script path a loaded skill names is carried on the request and asks on its own; a command granted at project scope does not approve a skill's script, and both surfaces print the path and its skill |
| Free mode and launch freshness | **real**: opening the window forces the work rather than trusting a cache — every credentialed provider's roster is read concurrently, and skill sources (GitHub repositories and the marketplaces) are re-synced through `SkillIndex::refresh_all` instead of waiting out the stale window. The picker's cache is 60 s rather than 300, and `models_refresh` re-reads on demand. **Free mode** ranks tool-capable free **chat** rows by a checked-in benchmark snapshot, sends up to six of them a real 8-token message, skips 401/429/404/400 and settles on the best-ranked one that answers; the provider and model are saved through the same path as a manual pick, native fan-out (`SubagentPolicy`) runs on that same free model, and the Chat room's Swarm preflight installs a managed `@rigel-free` API agent on it. Tests: `agent::freemode` (benchmark ranking, tool-capable filter, failure classes, a 429 row skipped for the next candidate) and `agent::agentchat` (managed config table) |
| Destructive commands | **real**: a deterministic classifier maps a command to policy rows — `delete-outside-project`, `recursive-remove`, `force-push`, `git-reset`, `registry-write` — before approval; the prompt names the rows and the matched token, and the `command` item records them. **Q239:** the same classifier produces a `BlastRadius` carried on `CommandRequest` to both the window card and the CLI question: exact command segments, resolved paths, file/byte counts where provable, and explicit `cannot_determine` rows. It never executes or guesses, and the post-approval snapshot remains the recovery path |
| Snapshots | **real**: before an approved destructive command, `git stash create` object (kept alive by `refs/rigel/snapshots/<id>`) plus raw copies of changed and untracked files; a non-git tree or a repository with no commit is copied whole; 2 000 files / 200 MB cap, refusing above it. Every copied file carries a SHA-256; restore verifies the snapshot copy before writing and each target after, naming the differing path. `rigel snapshot capture\|list\|restore\|prune`; prune removes only old directories with no readable manifest or whose project root is gone, with `--dry-run` available. Older manifests without hashes restore as `unverified`. Tests: `crates/rigel-core/tests/snapshot.rs` and `crates/rigel-cli/tests/snapshot.rs` |
| Backups | **real**: `rigel backup create\|verify\|restore\|rotate\|drill` encrypts the global data directory with age and scrypt into a local `.rigel-backup` archive; a manifest at the end carries every relative path, byte length and SHA-256, the live `index.db` is copied with SQLite `VACUUM INTO`, and `backups/`, `updates/`, `diagnostics/`, `agentchat/` and WAL sidecars are reported exclusions. `create` verifies its own archive before publishing it; `verify` decrypts and checks every file; `restore` requires a new or empty directory and stages before renaming; `rotate` re-encrypts under a new passphrase and verifies the result; `drill` restores to a temporary tree, runs `PRAGMA integrity_check`, and records a receipt that `--max-age-days` makes scheduler-safe. Passphrases come from a file or environment variable, never argv ([backup](backup.md)). Tests: `backup::tests` and `crates/rigel-cli/tests/backup.rs` |
| Test selection | **real**: `rigel test plan\|run` reads tracked and untracked changes relative to `--since` (or explicit `--changed-file` paths), maps Cargo source to `cargo test -p <package>`, a Cargo integration test to its exact `--test` target, and JavaScript/TypeScript to the owning package's declared test script; documentation is reported as skipped. A manifest, lockfile, build/migration/workflow change, more than six source files, more than two Cargo packages, an unmapped source file, a generated/vendored source or `--full` adds the full suite. Selected targets run first and stop at the first failure; the full suite runs only after they pass, and every skipped path and risk reason is printed in human or JSON form ([test selection](test-selection.md)). Tests: `testimpact::tests` and `crates/rigel-cli/tests/testimpact.rs` |
| Deliberation | **real**: a destructive command first gets one round of three read-only advisors (advocate, opponent, referee) on the parent's model, billed to its own turn and shown before the approval prompt; the answers are advisory and cannot allow, deny or alter the gate. Scripted runs record that advice was not gathered instead of consuming their fixed steps |
| Egress | **real**: `fetch_url` asks per origin with `once` / `session` / `always` scopes (`always` persists in `<index dir>/approved-origins.json`), re-approves a redirect that crosses origins, reads only text-like content types, caps the body at 256 KB by default (the project limit can raise it to 4 MiB), and records the page as a `web_search` item with `untrusted: true`. **Q240:** `NetworkPolicy` in `.rigel/network.json` adds a project kill switch (`enabled: false` refuses before the prompt or socket), an optional origin allowlist, and `disabled_sessions` for one session without silencing the others; `network_get`/`network_set`, `rigel agent run --no-network` and repeated `--allow-origin` all use it. **Roadmap 61:** the file now holds ordered allow/deny `rules` (exact origin, bare host, `*.` subdomain wildcard, `*`, optional port), a `default` of `ask` or `deny`, the kill switch and disabled sessions; the first match wins, an allow rule still asks the per-origin question, and a legacy `allowlist` loads as allow rules with a deny default. `rigel network show\|check\|set` reads and writes the same file, `network_get`/`network_set`/`network_check` back Settings → Network, and a policy the matcher cannot enforce is refused on save rather than ignored on the next fetch | **Roadmap 62:** `EgressLimits` in the same policy caps requests per origin and per agent in a fixed window (with `retry_after_secs`), caps the response size, resolves a host twice and refuses a changed answer as `DNS_REBIND`, refuses loopback/private/link-local/metadata ranges unless opted in, and records the pinned address on `fetch_url`, the `browser_open` preflight and Exa results (the Obscura subprocess still makes its own connection, so its engine is not host-pinned; it is told whether private targets are allowed); `rigel network check --resolve` is the dry run and Settings → Network edits the limits.
| Sandbox profiles | **real** (opt-in): `crates/rigel-core/src/sandbox` defines `SandboxProfile::None`, `JobObject`, `SandboxExec` and `LinuxNamespaces`; `Tools::with_sandbox` applies one to an approved `run_command`, and a profile that cannot be prepared or attached refuses the command with `SANDBOX` rather than running unsandboxed. Windows Job Objects use `KILL_ON_JOB_CLOSE` and optional active-process/job-memory caps and are exercised by real allow/finish and kill-on-close tests; macOS `sandbox-exec` writes an SBPL profile that limits writes to configured roots and denies network unless enabled; Linux uses `unshare` user/mount/PID/network namespaces. Every profile has a written `containment()` statement naming both blocked and allowed capabilities. **Known limits:** Job Objects do not restrict files or network; macOS `sandbox-exec` is deprecated; Linux `unshare` needs usable user namespaces and its mount namespace alone does not remount the filesystem. |
| Exa | **real**: the native agent's `web_search` and `web_fetch` tools read through Exa's API (`api.exa.ai`), not a harness MCP server. Search returns ranked titles, URLs, dates and extracted text (`/search` with `contents.text`, capped per result); fetch returns one page as clean Markdown through `/contents`, so JavaScript-rendered pages, PDFs and complex layouts work where `fetch_url`'s raw text does not. The key is the keychain entry `exa` (`rigel keys set exa`) or `EXA_API_KEY`; it is read through `credentials`, so it never appears in a tool argument, a transcript or a log. The origin is fixed and chosen by Rigel, so there is no per-site card, but the project `NetworkPolicy` kill switch and allowlist are checked before every request, and both tools carry `untrusted: true` with the no-permission note. Subagents may use both; the researcher role lists them. Tests: `agent::exa` (URL validation, result shaping and capping, unreadable-page errors) plus an ignored live search→fetch test |
| Subagents | **real**: `spawn_agents` starts up to 4 read-only children in the background on an eight-model cheap allowlist (GPT-5/5.4 nano, Gemini Flash-Lite/3 Flash, DeepSeek V4.1 Flash, Qwen3 Coder, Haiku 5.5, GPT-5.4 mini); each child is its own agent row and bill, nested under the parent turn, and must be given a role, an explicit file list and a task. The parent returns at once, can `chat_send`/`chat_wait` with the children in the session room while they run, and collects them with `subagent_results` before finishing. The split is recorded on the session work board, every child sees it and may read only its own files, and each starts its answer with the files it worked on; `assign_agents` gives the same file-scoped work to agents already in the chat room. **Write mode (D80)** gives a child its own worktree, a claim on each assigned file and the full tool set scoped to that list; its work lands only through `merge_subagent`, which reviews the diff with clean context, stores the verdict and merges through the CAS journal. The allowlist is OpenRouter-shaped, so the tool is hidden on the Gemini and Anthropic providers — whose namespaces would replace every id with their own default — rather than handing them ids their endpoints reject. **Q245:** every child gets `SubagentPolicy::max_steps` as its own coordinator bound; it cannot spend the parent's remaining steps, and the cap is recorded as `step_limit`. **Roadmap 44:** a child below `max_depth` may spawn one more read-only generation, but every level shares the root's `TreeBudget`; a spawn at the cap is refused with `DEPTH_LIMIT` naming the cap, and the session graph stores each node's depth and remaining inherited budget |
| Safety defaults | **real**: three writable children at once (D113), a per-child plan the user approves or skips with a reason (D114), a blocking clean-context reviewer on every writable merge with a recorded override (D115), and a $20/day cap across the project that refuses a turn before it starts and interrupts every running agent after the step that crosses it (D116). Settings → Safety edits the cap and the writable count and shows today's ledger |
| Permission matrix | **real**: `.rigel/permissions.json` is the project tool ceiling; a missing file keeps every tool, an empty grant denies every tool, and malformed/unknown entries are refused instead of falling open. `ProjectPermissions::effective_for_agent` intersects the ceiling with the four role presets and an optional per-agent override stored in `agents.tool_overrides` (migration 0024). `Tools` enforces that intersection on both the offered schemas and the real dispatch path, and the coordinator checks it before its own special-tool dispatch; `Tools::new` reads the file too, so the direct `rigel serve` command route cannot skip it, and the coordinator reloads it at the root of every turn. A spawned child is clamped to its parent's effective grant at spawn as well as the project, its role and its override, so delegation cannot hand it a tool the parent lacked. Settings → Permissions shows one table with the project grant, each role and each open agent's effective grant; agent cells save narrowing overrides through `permissions_set_agent`. Tests: 6 `permissions` unit tests, 9 real `Tools`/coordinator tests, and `ui/tests/permissions.spec.ts` (including an agent override). **Known limits:** tool names only (commands and MCP tools keep their own approval scopes); an override can only remove tools the role and project already allow; a saved all-tools list needs re-saving after a build adds a tool; no CLI subcommand was added |
| The bill | **real**: micro-dollar accounting from provider usage, local price fallback, 80% warning, cap enforced within one turn, `reconcile` |
| Session surface | **real**: roster with a manual `+ agent` form, role-gutter transcript, streaming text, collapsed tool lines, patch diffs, raw/debug toggle, inline 80% prompt, two agent transcripts side by side (a running subagent appears as soon as its turn starts), a live model and effort picker that merges the current provider with OpenRouter's full roster and switches provider with the picked model, **Roadmap 58:** each roster row has its own model/provider/effort picker, a role preset overrides the row (the picker is disabled and tagged `preset`; `custom` keeps the pair), and the composer's `next` chip shows the model, effort and source before Send; a Swarm button that wakes the room, asks for the big boss (Rigel, the Muse coordinator, by default) from the full chat roster, then sends the typed task to the agents you keep ticked. **Q254:** Pause/Resume call `turn_pause`/`turn_resume`; the coordinator waits at the next step boundary, writes `paused`/`resumed` rows, and resumes the same turn with its message list and remaining budget |
| Patches | **real**: CAS check, write-ahead journal, fsync + rename, idempotent apply, revert once applied |
| Resume | **real**: tree hash vs checkpoint, running turns closed as `cancelled`, journal reconciled without applying, forced continue is an intervention |
| Memory | **real**: committed `MEMORY.md` + topics per agent, absolute-path/secret validator, index rebuild. **Roadmap 55:** every non-heading line is a fact ranked by recency (30-day half-life), use and pin, with every factor's value, weight and reason returned; a pinned fact's recency is held at full and never decays. `rigel memory rank` prints the arithmetic and `rigel memory pin` toggles it; the session inspector's Memory panel shows the same three factors and offers Recall and Pin. **Q251:** `MemoryService::new` defaults to `DenyMemory`; a write needs an installed `MemoryApprover`, and the window card, CLI `y/yes` prompt and MCP bus all show the exact path/mode/content. Validation runs before the question; `NotApproved` writes nothing |
| MCP | **real**: stdio server scoped to `--session` and `--agent`, sharing the same tools. **Q242:** a project server declared in `.mcp.json` is refused until the card answers, and the card shows the server's **real** `tools/list` — read by a bounded stdio `initialize` → `tools/list` handshake, not guessed from the file. The server grant is separate from the tool grant: each tool asks on its first use with its description and schema, and each decision is recorded with `gate: "Q242"` on the turn (or as an `mcp_approval` intervention when a harness turn has no row). **Roadmap 68:** `.rigel/mcp-pins.json` stores the server version, a canonical catalogue hash and every tool definition; an added or schema-changed tool is refused with `MCP_SCHEMA_DENIED` until the `mcp_schema` card shows the before/after diff and is accepted. Project/Always updates the pin, This session accepts it for this process, Allow once accepts one call; a malformed or unreadable pin fails closed with `MCP_PIN_INVALID`. The process caches its `tools/list`, so an update is seen when it next lists. Tests: `crates/rigel-mcp/tests/project_mcp.rs` and 7 `mcp::pin` unit tests |
| Codex harness | **real**: `rigel codex probe` and one turn through `codex app-server`, with `codex exec --json` as the tested fallback; Rigel writes the router `-c` overrides itself (verified against Codex 0.162.1) |
| Claude harness | **real**: `rigel claude probe` and one turn, recorded as a session turn and billed with the CLI's own `total_cost_usd`; the turn passes `--mcp-config` and `--permission-prompt-tool mcp__rigel__rigel_approve`, and the CLI answers each question on stdin with the same four scopes as the native agent. Protocol verified against a scripted 2.1.251 stream; a live subscription turn has not been run.
