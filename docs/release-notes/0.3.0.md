# Rigel 0.3.0 — the full release notes

**Prepared:** 22 November 2026 · **Version:** 0.3.0 · **Status:** source-only, not tagged or published

Rigel 0.3.0 is the first release built around the full 0.3 tree: a routed agent runtime, a
capability-bound plugin system, a project permission matrix, a merge queue, and a window that
finally shares one visual language across Home, Shelf, Session, Chat, Diff and Settings.

This is a **source release**. The newest published installer is still 0.1.7; 0.3.0 has no signed
MSI, NSIS bundle or provenance receipt yet. Build from source until that release is cut.

## Why this release exists

0.2.0 proved that several agents could share one project database. 0.3.0 is about making that
shared tree survivable and legible:

- every model choice goes through one resolver;
- every turn can be paused, steered or recovered;
- every child agent is clamped to the tools its parent has;
- every plugin call crosses a capability broker;
- every write names its lane and its reviewer;
- every surface uses the same typography, tokens and card language.

## Window and interaction

- **The Rigel Paper.** Home is a broadsheet derived from the project database: a lead story per
  session, dispatches from commands, patches and notes, a deterministic plate when no browser frame
  exists, the day's turns, patches, tokens and cost, and a rack of earlier editions.
- **A more legible paper.** Warmer stock, an amber masthead rule, a flagline, a section ornament,
  a pull-quote prompt, stronger archive cards and consistent front-page rules. The idle edition
  uses the same masthead.
- **Grouped Settings.** Twenty pages now sit under Agent, Guardrails, Workspace, Connections,
  Window and System. Search filters within groups and hides empty groups.
- **Foldable notes.** The Settings notes rail folds from the header or its own control, gives its
  grid column back to the page, and remembers the choice in `localStorage`.
- **Shelf and Chat match Settings.** Both surfaces use the same 20px rail title, group labels,
  rounded rows, amber selection marker, large page header and card sections. Shelf's catalogue
  tabs are a full-width segmented control; Chat's room header and composer share the page rhythm.
- **One amber composer.** Build uses the amber accent with dark text instead of the old green
  button; changed skill pins use the same accent family.
- **Terminal removed.** The rail tab, command-palette action, Settings page, component, xterm
  dependency, terminal API and its tests are gone. The integrated terminal was not part of the 0.3
  product and left a second, inconsistent command surface.
- **Casing pass.** Reader-facing labels use IDs, PIDs, humanised transport and tier values, and
  named sources (GitHub, SkillsMP, SkillHub) instead of storage keys. About reads the renderer
  version from `package.json` instead of the old hardcoded 0.1.7.

## Plugins, skills and the shelf

- **Plugin protocol.** A `plugin.json` manifest (schema 1) with unknown fields refused, a
  short-lived child per tool call, a scrubbed environment, and a capability broker that
  canonicalises every `fs.read` and `fs.write` against declared roots.
- **Install receipts.** An install stores the tree SHA-256 and the reviewed manifest hash. A
  rewritten manifest is refused rather than widening its grant. Enable, disable and remove keep
  the tree on disk until removal; a broken tree remains removable.
- **Catalogue.** The embedded catalogue has **2,533 entries**: nine bundled skills, the first-party
  `rigel-hello` plugin and 2,523 external listings. It is searchable offline, carries
  official/verified/community tiers, capability chips, licences and exact install commands, and
  never pretends an external listing can be installed by Rigel.
- **Nine native skills.** SkillEvaluator, Headroom, AG-UI, mcptoon, llmfit, Semble, Cognee
  evaluate-only, Blender MCP and Superpowers are indexed at launch and installable into the
  harness stores.
- **Shelf detail.** Grade, source, stars, tokens, last-seen time, evidence table, static review
  with `file:line` evidence and duplicate variants remain one click from the list.
- **Shared catalogue UI.** Settings → Plugins and the Shelf's Plugins tab read the same store, so
  installs, toggles and broken trees cannot disagree.

## Agents, routing and runtime

- **One route resolver.** Saved pairs, picker pairs, role presets and bare-id repairs all pass
  through the same resolver. The inspector and `rigel route explain` print selected, requested,
  resolved, reason and any mismatch sentence.
- **Provider health.** Launch probes every credentialed door. A dead provider becomes a health row
  instead of silently changing the model. Aliases resolve to the pair they name.
- **Local and custom doors.** Ollama and llamafile need no key; a custom OpenAI-compatible door is
  validated and written only to the OS keychain. OpenRouter provider order, fallbacks and
  quantisations live in `.rigel/routing.json`.
- **Per-agent configuration.** Each roster row can carry its own model, provider and reasoning
  effort. A role preset overrides it; the next turn's pair is shown before send.
- **Plan mode.** One plan approval, and a tool outside the approved set re-arms the approval gate.
- **Steering and pause.** Steer at a step boundary, pause across a restart with the same messages
  and budget, continue with a fresh bound, and recover a crashed turn with resume, read-only or a
  discard tombstone.
- **Subagent DAG.** Four read-only roles by default. A writable child gets a worktree, per-file
  claims and a clean-context review before its merge.
- **Compaction and summaries.** One deterministic, extractive summary per finished turn is stored
  with its item ids; compaction reads those summaries at 80% of the context window instead of
  walking dropped items. Palette search matches them first.
- **Tool-call repair and context budget.** Malformed tool calls are repaired against the schema;
  prompt sections and per-step cost are measured rather than guessed.
- **`rigel handoff`.** Package the newest unfinished session as a rules-preserving prompt with
  constraints, changed paths, `git status`, a bounded diffstat and open questions. Nothing is
  marked done and model output is labelled unverified.

## Safety and permissions

- **Project permission matrix.** `.rigel/permissions.json` is the tool ceiling. Roles narrow it,
  per-agent overrides narrow the role further, and no layer can widen the project grant. A spawned
  child is clamped to its parent's effective grant at spawn.
- **Network policy.** Ordered allow/deny rules, a default decision, disabled sessions, per-origin
  and per-agent caps, validated DNS pinned to the connected address, and private targets refused
  by default.
- **Sandbox profiles.** Opt-in Windows Job Objects, macOS `sandbox-exec` and Linux namespaces for
  approved commands. A profile that cannot be prepared refuses the command instead of running it
  unsandboxed; each profile states what it does and does not contain.
- **Approval chain.** Exact command text, cwd and timeout; destructive commands name their policy
  rows, receive one round of three read-only advisors, and capture a snapshot before approval.
- **Write-time defences.** A file jail, pre-write secret scanning, redaction, prompt-injection
  tagging, migration-prefix rehearsal and a bounded redacted diagnostic ring.
- **MCP pins.** Project servers pin their version and tool schemas; added or changed tools stay
  blocked until the schema diff is accepted.
- **Snapshot integrity.** Per-file hashes are verified before restore; pruning only removes old
  orphan snapshots.

## Storage, claims and merge

- **Claims remain advisory.** Tombstones, a 24-hour expiry, stale rows that are never
  auto-released, and a 250 ms attribution watcher that names a writer or marks ambiguity.
- **Merge queue.** Every proposal, apply, revert, worktree merge and conflict write takes a
  per-path writer lease before its CAS read. A second writer waits, names the holder and cannot
  enter the same path. Different paths keep separate lanes.
- **Three-way merge.** Base, ours and theirs are rendered per conflicted hunk. The guided editor
  requires an explicit ours/theirs/edit decision for each hunk, stores the reviewer, choices,
  acknowledgement and merged hash in `conflict_verdicts`, and refuses unresolved marker blocks.
- **Memory ranking.** Every non-heading memory fact is ranked by recency, use and pin, with all
  three factors exposed. A pinned fact holds full recency. Writes require an approver and show the
  exact path, mode and content.
- **Migrations.** 0019 conflict verdicts, 0020 memory facts, 0021 session title source, 0022 turn
  summaries, 0023 agent model configuration and 0024 per-agent tool overrides apply in order.

## Harnesses and adapters

- **Unified event renderer.** Claude, Codex, Muse and ACP events pass through one tested normaliser
  and a dated parity matrix.
- **Claude Code.** One real turn with `--mcp-config`, the approval prompt tool and all four answer
  scopes, billed from Claude's own `total_cost_usd`.
- **Muse Code.** Headless `muse exec --json` turns, items and usage without invented numbers.
- **ACP harnesses.** Gemini CLI, Cursor and Cline one-turn ACP runs, including both sides of every
  permission request and per-harness key checks.
- **Known verification limit.** Gemini CLI, Cursor, Cline and Muse Code were exercised against
  scripted implementations on this machine; none of those CLIs was installed for a live turn.
  Claude was verified against a recorded 2.1.251 stream, not a live subscription.

## API, cloud and deployment

- **`rigel serve`.** The coordinator over loopback HTTP with bearer auth, an OpenAPI 3.1 document
  and SSE. It binds loopback by default and refuses `0.0.0.0`.
- **Cloud is opt-in.** A Firebase project you own; Identity Toolkit sign-in, Firestore mirroring
  with tombstones, one session published to the phone, App Check verification and no telemetry.
  Tool calls, command output and project paths never leave the machine.
- **Web and CMS.** The static site, Fastify API, Payload CMS, Caddy edge and Postgres databases have
  a deploy runbook and a local checker. The VPS API is still partial: health, auth, devices,
  sessions, published sessions and the relay are implemented; several routes still live on
  Firebase.
- **iPhone.** The read-only client is compiled with unit coverage, but was not device-tested.

## Upgrade notes

1. **The Terminal tab is gone.** Use an external terminal or the host CLI for shell work.
2. **Run the migrations.** 0019–0024 apply automatically when the project opens; applied
   migrations are immutable.
3. **Review plugin grants.** A plugin's capabilities are declarations, not syscall interception.
   Review the tree and use an OS sandbox where available.
4. **No signed 0.3.0 installer.** Building from source needs Rust 1.88+, Node 22.12+ and npm.
5. **Casing is display-only.** Storage keys such as `github`, `skillsmp`, `streamable-http` and
   `plugin` are unchanged; only the reader-facing labels are capitalised.

## Verification receipt

On 22 November 2026 the local gate passed:

- renderer `tsc --noEmit` and Vite production build;
- the token-only design audit across 51 UI files;
- documentation, roadmap, privacy, claims and version checks;
- the 63-test Playwright suite;
- the native Tauri window lane for open, turn, approval and diff;
- the README media pass, with every referenced still and GIF present.

The signed installer, live external CLI turns, a live Firebase project and a device-tested iPhone
client remain open proof, not shipped claims.

## Known gaps

- No signed 0.3.0 installer or provenance receipt.
- VPS API routes are partial and the web reader still talks to Firebase.
- Cloud was exercised against a local Firebase stand-in, not a repository-owned live project.
- The iPhone client is compiled, not device-tested.
- Gemini CLI, Cursor, Cline and Muse Code were verified against scripted implementations.
- A static capability scan is not proof that a skill is harmless; grade `A` is unreachable from a
  static scan and stays reserved.
- The merge reviewer is a model, not a proof; the journal and worktree make a bad merge
  recoverable.
- Plugins are subprocesses; the broker does not intercept the plugin's own syscalls, and
  `network`/`process` are declarations.
