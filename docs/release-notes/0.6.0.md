# Rigel 0.6.0 — stable

Rigel 0.6.0 is the first stable release since 0.1.7. It promotes the 0.4 code line, which had only
a Windows pre-release, and includes the fixes that line needed before it could be called stable.
It carries the features and fixes from the 0.4.0-1 and 0.4.0-2 changelog entries.

## Security and local data

- **OIDC and SAML enterprise SSO** for the self-hosted API, with domain discovery, PKCE and nonce
  checks, signed SAML assertions, replay protection, enforced SSO for a configured domain, and a
  listed break-glass admin. The tests run a real HTTP OIDC provider and a signed SAML IdP through
  the login round trips and their failure paths ([sso](../sso.md)).
- **Opt-in SQLCipher 4 encryption** for `.rigel/rigel.db`. The 32-byte key comes from
  `RIGEL_DB_KEY` or the OS keychain; plaintext databases migrate in place with an integrity check;
  a missing or wrong key fails closed. The vendored binding uses SQLCipher 4.20.0 / SQLite 3.54.1,
  so the bundled database includes the fix for RUSTSEC-2026-0502 / CVE-2026-119375
  ([encryption](../encryption.md)).
- **Skill publisher signatures and SkillSpector.** An Ed25519 signature and the SHA-256 of a
  skill's instructions are verified before `skill_load` returns a body; unsigned downloads need an
  explicit trust file. Third-party repository walks and installs are scanned, and a missing
  scanner, unreadable report or error exit fails closed ([skill intelligence](../skill-intelligence.md)).
- **A narrower API and cloud surface.** `rigel serve` checks `Host`, compares bearer tokens through
  fixed-length digests and limits failed authentication; cloud access tokens pin HS256; relay JSON
  is bounded; swarm job ids are unpredictable v4 UUIDs.
- **Audit and backup receipts.** Settings → Audit log filters the hash-chained approval ledger by
  project, session, agent, turn, decision and text and exports exactly the matched rows. Encrypted
  local backups support `create`, `verify`, `restore`, `rotate` and `drill` with a SHA-256 manifest,
  a consistent SQLite snapshot and staged restores ([audit](../audit.md), [backup](../backup.md)).

## Agents, models and updates

- **Image-bearing turns** are carried through the adapter boundary and persisted with the turn.
- **NVIDIA NIM** joins the hosted provider doors.
- The live model roster refreshes every three minutes, and `free_agents` returns ranked zero-priced
  chat rows without probing them.
- A newer release is applied through a detached helper; the previous binary is kept until the
  relaunched build reports its window up, and a build that never does is rolled back and skipped
  for 24 hours ([updates](../updates.md)).
- `rigel doctor` reports the update channel, current version, manifest URL and last receipt.
- The window waits for the API before showing itself, so a slow start is a wait rather than a blank
  frame.

## Testing and release work

- `rigel impact` maps changed symbols to their imported or qualified references and exact test
  targets; `rigel test plan|run` selects impacted tests with a full-suite safety net; `rigel test
  flakes` hunts outcome-changing tests; `rigel proof` records checkable evidence and marks it stale
  ([impact](../impact.md), [flakes](../flakes.md), [proof](../proof.md)).
- The Windows, macOS x64, macOS arm64 and Linux x64 bundles all build in CI.
- The `rigel-b` license resource no longer collides with the sidecar name, so the macOS and Linux
  bundles stop failing with `File exists (os error 17)`.
- At narrow widths the composer reserves a right-hand gutter, so the account/settings pair no
  longer covers Send or Stop.
- The supply-chain gate explicitly allows the SQLCipher bundle's SQLite blessing and libtomcrypt
  WTFPL notices.

## Install

Windows 10 1809+ x64. The NSIS installer, MSI, raw executable, signed `latest.json` and SBOM are
attached to the release. This is a stable release, so `releases/latest` and the default stable
updater feed point at 0.6.0. The Windows installers are unsigned, so SmartScreen may warn; the
update manifest is Ed25519-signed and every published asset has a SHA-256.

The macOS and Linux bundles build in CI but are not published. macOS still needs signing and
notarisation; no Linux package is verified for distribution.

## Known limits

- The code graph is name-based, not type-checked.
- Concept nodes depend on a configured OpenRouter key and a live free row.
- The graph watcher follows one project at a time.
- The Windows installers are unsigned; only the update manifest is signed.
